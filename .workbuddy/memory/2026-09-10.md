## 修复 RangeError: Invalid string length（超大工程）

- 现象：用户配置 @Service/@CloudComponent/@Component 跑真实工程，`src/index.ts` 第 172 行 `JSON.stringify(result, null, 2)` 抛 RangeError（超出 V8 单字符串 ~512M 字符上限）。
- 根因：一次性 stringify 整个 ParseResult / Graph，且 HTML 里还内嵌了整份 JSON。
- 方案：新增 `src/utils/stream-writer.ts`
  - `jsonChunks(value, indent)` — async generator 分片序列化（数组逐元素、对象逐键），永不构造大字符串；输出与 `JSON.stringify(v, null, indent)` 逐字节一致（已验证）。
  - `writeChunks()` 按 `stream.write` + `once(stream,'drain')` 处理背压；`writeJsonFile()`；`writeHtmlWithJson(head, value, tail)` 流式拼装内嵌 JSON 的 HTML。
  - 内嵌 JSON 统一用 `\u003c` 转义 `<`（JSON 合法转义，可防提前闭合 script）。
- 渲染器拆分：graph / trace / annotation 三个渲染器各自导出 `xxxParts()` 返回 `{head, tail[, data]}`，模板里用 `\u0000` 占位符切分；`renderGraphHtml()` 等仍保留（小数据直接返回字符串）。
- 新增配置：`AppConfig.jsonIndent`（默认 2，0=紧凑）、`AppConfig.skipJson`；CLI `--json-indent` / `--no-json`。
- 验证：2000 文件 / 2000 类 / 14087 节点压测通过，big.json 11.5MB、graph.html 6.7MB、注解页 667 条分页正常；`--no-json` 跳过落盘生效；序列化与原生 stringify 逐字节一致；临时工程与 big.* 产物已清理。
